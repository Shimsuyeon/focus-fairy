# 집중요정 사용 현황 (/usage)

운영 KV를 **읽기만** 해서 합계를 내는 로컬 스크립트(`scripts/usage.mts`, 로직은 `src/services/usage.ts`)를 돌리고 결과를 요약한다. 서버에 운영자용 페이지는 두지 않는다.

## 실행

```bash
npm run usage --silent              # 터미널 표
npm run usage --silent -- --json    # 숫자를 더 따져봐야 할 때 (같은 내용, JSON)
```

- 인증은 이미 로그인된 wrangler를 쓴다. "KV 키 목록을 읽지 못했어요"가 나오면 사용자에게 `! npx wrangler login` 을 안내한다.
- Node 22.6+ 필요 (TypeScript를 그대로 실행).

## 요약하는 법

출력을 그대로 붙여넣지 말고, 사용자가 물은 것에 맞춰 짧게 정리한다.

1. **한 줄 결론**: 지금 실제로 쓰는 워크스페이스 수와 7일 사용자 수.
2. **워크스페이스별 변화**: 활동 중인 곳, 마지막 기록이 오래된 곳(멈춘 날짜), 처음 등장한 곳.
3. **추이**: 주별 사용자·신규·유지율에서 눈에 띄는 변화 (급감한 주, 신규가 생긴 주).
4. **기능**: 익스텐션 시작/종료 비율, 기록만, 카테고리·계획·쉬어가기 비율. 출처는 #75 배포 이후 세션부터 기록되므로 그 전 기간의 0%는 "아직 데이터 없음"으로 읽는다.
5. ⚠️ 24시간 넘게 켜진 세션이 있으면 알려준다 (끄는 걸 잊은 세션).

알아둘 것:
- `T0A2SV0H1QV`(Goal Mate)는 봇 토큰이 KV가 아니라 시크릿에 있어서 이름 대신 ID로 나온다. **Goal Mate는 사용자의 실제 워크스페이스, My Dream(`T0A80T0TWLB`)은 테스트용**이라 실사용 판단에서 My Dream은 따로 본다.
- 숫자는 집중 기록이 있는 사용자 기준이다 (설치만 하고 안 쓴 사람은 안 잡힌다).

## 하지 않는 것

- 개별 세션 기록, 사용자 ID, 계획 내용을 직접 읽거나 출력하지 않는다. `wrangler kv key get` 으로 `:sessions:` · `:checkin:` 값을 따로 열어보지 않는다. 더 자세한 숫자가 필요하면 `src/services/usage.ts` 에 **합계 항목을 추가**하는 방향으로 제안한다.
- KV에 쓰지 않는다.
